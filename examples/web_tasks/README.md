# Личный планировщик задач

Третий полный Web-проект: регистрация, вход, выход и личные задачи. Есть HTML-формы и JSON API. Каждый пользователь читает и меняет только свои записи.

## Локальный запуск

Из корня PythonTech, в окружении Python 3.10+:

```bash
python -m pip install -r examples/web_tasks/requirements.txt
python -m flask --app examples.web_tasks.app run
```

Открой `http://127.0.0.1:5000/`. Используй вымышленные учебные аккаунты. Имя: 3–32 латинские буквы, цифры или подчёркивания. Имена приводятся к нижнему регистру. Пароль: 12–128 символов. Остановка — Ctrl+C.

Данные находятся в `tasks.sqlite3` рядом с `app.py`. Перезапуск сохраняет задачи и аккаунты.

| Переменная окружения | Назначение |
| --- | --- |
| `TASKS_DB` | Путь к SQLite-файлу; родительская папка должна существовать |
| `TASKS_SECRET` | Постоянный случайный ключ подписи сессии; не публикуй его |
| `TASKS_ENV` | Значение `production` требует ключ длиной от 32 символов и включает Secure-cookie |

Без `TASKS_SECRET` локальный запуск создаёт временный ключ. После перезапуска войди снова и обнови формы. Для генерации ключа можно использовать `python -c "import secrets; print(secrets.token_hex(32))"`. Передай результат через окружение, не записывай его в исходники.

## Как проходит запрос

1. `before_request` загружает пользователя по сессии и проверяет CSRF для изменений.
2. `login_required` отклоняет гостя с кодом 401.
3. `owned_task` выбирает задачу одновременно по `id` и владельцу из сессии.
4. Проверка ввода выполняется до записи. UPDATE и DELETE также ограничены владельцем.
5. Форма получает перенаправление 303, API — JSON или пустой ответ 204.

Пароль преобразуется `generate_password_hash`, проверяется `check_password_hash` и не передаётся в ответах. Чужая задача возвращает 404, как отсутствующая. Вход очищает старую сессию и меняет CSRF-токен.

## JSON API

Клиент должен сохранять cookie. Сначала вызови `GET /api/csrf`. Перед каждым изменением передавай полученное значение `csrf` в заголовке `X-CSRF-Token`. После входа получи новый токен; после выхода старый больше не подходит.

| Метод и путь | Данные / результат |
| --- | --- |
| `GET /api/csrf` | Токен текущей сессии |
| `POST /auth/register` | `username`, `password`; 201 или 409 для занятого имени |
| `POST /auth/login` | `username`, `password`; 200 или 401 |
| `POST /auth/logout` | Пустой JSON-объект; 200 |
| `GET /api/tasks` | `items`: только свои задачи |
| `POST /api/tasks` | `title`; 201 и заголовок Location |
| `GET /api/tasks/1` | Одна своя задача или 404 |
| `PATCH /api/tasks/1` | `title` и/или логическое `done`; 200 |
| `DELETE /api/tasks/1` | 204 |
| `GET /health` | `{"status": "ok"}` |

Передавай `Content-Type: application/json`. Входные `done` — `true`/`false`, в ответах SQLite хранит и выдаёт `0`/`1`. Заголовок задачи содержит от 1 до 120 символов после удаления пробелов по краям. Плохой ввод и CSRF дают 400, неподдерживаемый формат тела — 415. Тело ограничено 16 КиБ; превышение при чтении даёт 413. Владелец всегда берётся из сессии.

## Тесты и запуск через WSGI

```bash
python -m unittest discover -s examples/web_tasks -p "test_*.py" -v
python -m pip install waitress
waitress-serve --host=127.0.0.1 --port=8080 --call examples.web_tasks.app:create_app
```

Тесты используют временную базу. Проверяют настоящий вход, неверный пароль, двух пользователей, чужие операции, CSRF, HTML, сохранение и настройки cookie. После запуска Waitress открой `http://127.0.0.1:8080/health`, затем проверь вход и создание задачи.

## Самостоятельные расширения

1. В проекте «Пользователи» добавь срок задачи, проверку даты и фильтр просроченных задач.
2. В итоговом проекте добавь личные категории, совместные фильтры и пагинацию. Не позволяй привязать задачу к чужой категории.
3. Раздели исходный однофайловый пример на Blueprint и модуль хранения. Сохрани поведение тестами.
4. Добавь отдельную функцию HTTP-клиента для `/health` каталога. Адрес задай конфигурацией, установи таймаут, проверь ошибки подменой сети.
5. Подготовь миграцию, проверку резервной копии и README для своей версии.

Образец не содержит этих расширений: их нужно написать самостоятельно. Критерии завершения курса — в [Web-руководстве](../../docs/WEB_GUIDE.md).

## Границы учебного проекта

Пример предназначен для localhost. Здесь нет ограничения попыток входа, восстановления пароля, проверки почты, централизованного отзыва сессий и постраничного вывода задач. Их необходимость нужно оценить до публичного использования.

Режим `production` проверяет секрет и включает Secure-cookie, но сам по себе не настраивает HTTPS, прокси или сервер. Для публичного запуска нужны также HTTPS, управление процессом, резервные копии и ограничение запросов. Не включай этот режим для обычного HTTP на localhost: браузер не отправит Secure-cookie.
