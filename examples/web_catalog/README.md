# Каталог книг

Второй полный Web-проект: SQLite хранит книги и категории, Flask выдаёт HTML и JSON. Поиск, категория и страницы списка работают вместе. Изменение данных через HTTP здесь не предусмотрено.

## Запуск

Из корня PythonTech, в окружении Python 3.10+:

```bash
python -m pip install -r examples/web_catalog/requirements.txt
python -m flask --app examples.web_catalog.app run
```

Открой `http://127.0.0.1:5000/`. Остановка — Ctrl+C. Если порт занят, добавь `--port 5001`.

При первом запуске создаётся `catalog.sqlite3` рядом с `app.py` с четырьмя учебными книгами. `CATALOG_DB` задаёт другой путь. Повторный запуск не заменяет существующие записи; отсутствующие начальные записи добавляются снова.

## Устройство

- `create_app` принимает настройки и создаёт таблицы.
- `books.category_id` ссылается на `categories.id`. Для каждого соединения включены внешние ключи.
- `selection` проверяет параметры, считает общее число совпадений и получает одну страницу через JOIN.
- HTML и JSON используют одну выборку. Поиск учитывает регистр и ищет буквальный фрагмент текста.
- Индекс ускоряет подходящие запросы по категории. Его пользу нужно проверять на реальных данных.

| GET-запрос | Результат |
| --- | --- |
| `/` | HTML-каталог |
| `/api/books?q=Python&category=1&page=1&limit=2` | `items`, `total`, `page`, `limit` |
| `/api/books/1` | Одна книга или 404 |
| `/health` | `{"status": "ok"}` |

По умолчанию `page=1`, `limit=2`. Допустимы страницы от 1 до 10000, размер страницы от 1 до 50 и поисковая строка до 80 символов. Неверные параметры дают 400. Пустой поиск — 200 и пустой список. Сортировка по уникальному `id` задаёт порядок страниц; при изменениях между запросами страницы могут сдвигаться.

## Проверка

```bash
python -m unittest discover -s examples/web_catalog -p "test_*.py" -v
```

Тесты создают временную базу. Они проверяют сочетание фильтров, границы страниц, кавычки в SQL, экранирование HTML и повторный запуск.

## Самостоятельный проект

1. Добавь таблицу авторов и ссылку автора у книги.
2. Напиши миграцию старой базы и проверь повторный запуск миграции.
3. Добавь фильтр по автору, сохранив остальные параметры.
4. Покажи автора в HTML и JSON через JOIN.
5. Проверь неизвестного автора, пустой результат и сохранение старых книг.

Готовность: можешь объяснить связь таблиц, порядок SQL-выборки и разницу между пустой страницей и отсутствующей книгой.
