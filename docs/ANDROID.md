# Android ARM64 — тестовая сборка

Android-версия готовится как **0.7.0-alpha.1**. Настольная версия 0.7.0 выпускается отдельно; существующий APK alpha.1 не содержит её изменений хранения данных.

## Для тестирования

- Архитектура: ARM64 (`arm64-v8a`). Минимальная версия: Android 9 (API 28).
- APK подписывается тестовым Android-ключом. Это не публикация в Google Play.
- Уроки и обычные подсказки работают офлайн. Внешний ИИ требует подключения к сети.
- Приложение показывает примеры, но не запускает Python-код ученика.
- Поддержка конкретного телефона подтверждается только после установки и запуска. Устройства с размером страницы памяти 16 КБ отдельно не проверены.

Скачайте APK из GitHub prerelease. Разрешите установку для приложения, которым открываете файл. После установки откройте любой урок, проверьте прокрутку, поворот экрана и сохранение прогресса после перезапуска.

## Сборка из исходников

Используются Python 3.11, PySide6 6.8.2.1, Buildozer 1.5.0, JDK 17, Android SDK 34 и NDK 26.1.10909125. Нужны Android wheels PySide6 и shiboken6 для `cp311`, `android_aarch64`. Скрипт закрепляет ревизию python-for-android.

[Инструкция Qt по Android](https://doc.qt.io/qtforpython-6.8/deployment/deployment-pyside6-android-deploy.html) описывает подготовку инструментов. Системные зависимости сборки должны быть установлены заранее.

Запустите из окружения Python 3.11:

```bash
python tools/build_android.py \
  --sdk /path/to/android-sdk \
  --ndk /path/to/android-sdk/ndk/26.1.10909125 \
  --wheels /path/to/android-wheels \
  --version 0.7.0-alpha.1
```

Скрипт копирует исходники в `build/android`, задаёт отдельную Android-версию и сохраняет APK в `dist/android`. Настольная версия в `main.py` не меняется. Локальные базы, настройки и ключи в исходники APK не копируются.

Для проверки подписи используйте `apksigner verify --verbose --print-certs <file.apk>` из Android SDK. Подпись Git-коммита и тега релиза проверяется отдельно на GitHub.
