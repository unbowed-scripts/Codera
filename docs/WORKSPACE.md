# Рабочее пространство 0.8.0

**Пиши и запускай свои проекты прямо в PythonTech.** Новые функции рассчитаны на настольную систему. Выпуск включает сборки Windows и Linux; macOS требует отдельной проверки.

1. Открой урок и нажми «Открыть рабочее пространство» в самостоятельной практике. После итогового теста раздела кнопка «Создать свой проект» открывает такое же пространство для мини-проекта.
2. Нажми «Открыть терминал». Если Python проекта ещё не подготовлен, появится предложение установить Python 3.13 или использовать выбранный Python. Через «Выбрать другой Python» можно указать установленный Python 3.10+.
3. Нажми «Установить и продолжить» или «Использовать выбранный Python». После успешной подготовки терминал откроется автоматически. Нужен интернет: в `.venv` устанавливается pip; в курсе Web — также Flask и requests. Повторная подготовка сохраняет существующие файлы окружения. Прерывание установки допускает повторную попытку.
4. Создай нужные файлы, напиши решение, сохрани его. Кнопка «Запустить файл» запускает выбранный `.py` через Python проекта. Она завершает предыдущий встроенный сеанс. Для Web оставь работающий сервер и открой указанный им адрес в браузере.
5. Для произвольных команд нажми «Открыть терминал». Терминал начинает работу в папке проекта с `.venv` в PATH. Примеры: `python main.py`, `python -m pip install flask`, `python -m unittest`. Ввод для `input()` отправляй прямо в терминале. Ctrl+C останавливает команду, Ctrl+Shift+C копирует выделение, Ctrl+Shift+V вставляет текст. Tab дополняет команду; Ctrl+Tab переводит фокус из терминала.
6. Сравни результат с задачей слева. Отметь каждый критерий и нажми «Готово». Это сохраняет самостоятельную отметку практики и открывает следующий урок либо итог раздела. Правильность кода не оценивается автоматически. Вопросы урока и итоговый тест остаются отдельными проверками; отметка практики не подменяет их результаты.

Терминал открывается в отдельном окне. В рабочем пространстве появляется сообщение «Терминал открыт в новом окне». Повторное нажатие показывает существующий сеанс. Окно можно развернуть на весь экран; задачи и кнопка «Готово» находятся слева. На узком экране кнопка «Задачи» переключает терминал и список критериев. Закрытие окна завершает сеанс, но оставляет редактор открытым.

В окне терминала нажми «Оформление». Выбери шрифт и размер, добавь свой TTF/OTF или переключи тему: тёмную, светлую, ночную либо свою. В своей теме задаются цвета фона, текста и курсора. Настройки сохраняются отдельно от темы приложения.

## Проекты и файлы

По умолчанию проекты лежат в `PythonTech Projects` внутри папки документов. В настройках можно выбрать другую папку. Core и Web разделены, а каждый урок и мини-проект имеет собственную папку со стабильным идентификатором. Смена названия урока не меняет путь. Смена общей папки проектов не переносит файлы: при необходимости перенеси их через файловый менеджер.

Редактор открывает текстовые UTF-8-файлы до 1 МиБ и показывает до 500 файлов, исключая `.venv`, `.git` и `__pycache__`. Вложенные имена вроде `templates/index.html` создают подпапки. Существующий файл не заменяется при создании. Символические ссылки редактор не открывает.

Ctrl+S сохраняет файл. Переключение файлов, запуск и выход из рабочего пространства также сохраняют изменения. Если файл изменён извне, сохранение и выход остановятся с объяснением: скопируй нужный текст, перечитай файл и объедини правки. Чек-лист сохраняется отдельно в настройках. Закрытие рабочего пространства завершает встроенный терминальный сеанс. Внешние терминалы остаются открытыми.

Код и команды выполняются с правами текущего пользователя: это обычный локальный терминал, а не изолированная среда безопасности. ИИ-помощник не получает автоматический доступ к файлам и терминалу; для подсказки код по-прежнему нужно передать явно.

## Другой терминал

В настройках укажи программу терминала и JSON-список аргументов. Каждый элемент списка передаётся отдельным аргументом, без склейки в команду оболочки. `{project}` заменяется полным путём проекта.

| Терминал | Программа | Аргументы |
| --- | --- | --- |
| Windows Terminal | `wt.exe` | `["-d", "{project}"]` |
| Konsole | `konsole` | `["--workdir", "{project}"]` |
| GNOME Terminal | `gnome-terminal` | `["--working-directory", "{project}"]` |
| Xfce Terminal | `xfce4-terminal` | `["--working-directory", "{project}"]` |

Пустое поле включает поиск установленного терминала. Внешний терминал может использовать уже запущенный сервер и собственное окружение. Если команда `python` указывает не на проект, используй `.venv/bin/python` на Linux/macOS или `.venv\Scripts\python.exe` на Windows. Оболочка встроенного терминала настраивается отдельно, например `/bin/bash`, `cmd.exe` или `pwsh.exe`.

Встроенный терминал использует PTY на POSIX и ConPTY/WinPTY на Windows. Он поддерживает текстовый ввод, управляющие последовательности, историю вывода и изменение размера. Цвета ANSI и выделение текста отображаются. Сложные полноэкранные TUI, мышь и все сочетания терминальных клавиш не гарантируются. Для них выбери внешний терминал.

## Python и ключи

Загрузка Python выполняется через [uv](https://docs.astral.sh/uv/guides/install-python/) и использует сборки Astral python-build-standalone. Интерпретаторы лежат в `python-runtimes` внутри папки данных приложения. Системный PATH и реестр Python не изменяются. В готовую сборку приложения входит uv; учебный Python скачивается отдельно. После установки код без новых внешних зависимостей можно запускать без интернета.

API-ключ сохраняется только после успешной проверки подключения и при включённой отметке сохранения. [keyring](https://keyring.readthedocs.io/en/latest/) обращается непосредственно к Windows Credential Manager, macOS Keychain или Secret Service на Linux. Сторонние файловые хранилища и запись ключа в QSettings не используются. При недоступном или заблокированном хранилище приложение сообщает, что ключ остаётся лишь в памяти.

При следующем запуске нажми «Подключить сохранённую модель»: запрос отправится по сохранённому адресу. Обычное отключение очищает ключ из памяти приложения, а «Удалить сохранённый ключ» удаляет его и из системного хранилища. Адрес API, название модели и признак сохранения остаются обычными настройками. Защита хранилища зависит от системы и учётной записи; она не защищает от программ с доступом к разблокированной учётной записи. Во время запроса ключ необходим в памяти процесса.

## Проверка перед выпуском

```bash
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software .venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/check_workspace_layout.py
.venv/bin/python tools/check_mobile_layout.py
.venv/bin/python tools/check_web_layout.py
```

Отдельная проверка с загрузкой Python и пакетов из интернета создаёт временный проект и удаляет его после завершения:

```bash
.venv/bin/python tools/check_workspace_runtime.py
```

Перед публикацией проверь Windows: ConPTY, пути с пробелами и кириллицей, Ctrl+C, закрытие с работающим сервером, Windows Terminal, установку Python и сохранение ключа в Credential Manager. На Linux/macOS дополнительно проверь настоящее системное хранилище с тестовым ключом и выбранный внешний терминал. Автотесты ключей используют подмену хранилища и не читают личные секреты.
