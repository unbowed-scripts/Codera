# Python Web: от запроса до самостоятельного приложения

**Курс даёт базовое понимание веб-разработки через 42 урока и семь мини-проектов.** Начни после Python Core: понадобятся функции, словари, исключения, файлы и тесты.

В каждом уроке есть теория, рабочий пример, два вопроса, самостоятельное задание и критерии. В конце раздела — шесть коротких вопросов, два вопроса по коду и мини-проект. Код ученика запускается отдельно: приложение проверяет ответы, а практику ты отмечаешь после самопроверки.

## Как проходить раздел

1. Запусти пример урока и сопоставь вывод с разбором.
2. Ответь на вопросы без копирования готового результата.
3. Выполни практику в своём файле и проверь все критерии.
4. Пройди тест раздела.
5. Запусти образец проекта, затем реализуй требуемое расширение самостоятельно.
6. Добавь тест на успех и хотя бы один отказ. Объясни, почему данные после отказа не изменились.

Не открывай сетевой доступ к учебным приложениям во время занятий. Локальный запуск позволяет изучить запросы, хранение и права без публичного сервера.

## Итоговая самопроверка

База усвоена, когда можешь выполнить следующие действия без пошаговой подсказки:

- Проследить запрос: URL → маршрут → проверка → SQL → ответ или HTML.
- Объяснить различие GET, POST, PATCH и DELETE; выбрать код 200, 201, 204, 400, 401, 404 или 409.
- Создать связанную таблицу, написать JOIN и добавить миграцию без потери старых записей.
- Добавить фильтр и страницы списка с проверкой входа и устойчивым порядком.
- Объяснить различие входа и прав доступа. Проверить чужое чтение, изменение и удаление двумя клиентами.
- Объяснить, почему нужны SQL-параметры, экранирование HTML, хеши паролей и CSRF: это разные задачи.
- Обработать таймаут и неверный JSON внешнего сервиса. Проверить это без интернета.
- Найти ошибку по тесту и логу. Не записывать секреты и пароли в журнал.
- Запустить приложение из нового окружения по своему README через WSGI на localhost.
- Восстановить тестовую базу из резервной копии и проверить её содержимое.
- Добавить одну небольшую функцию по своему плану, подготовить ветку Git и описание проверок.

Если трудно с данными, повтори разделы 3 и 5. Если с пользователями — раздел 6. Если с запуском и проверками — разделы 4 и 7. Само число завершённых уроков не подтверждает готовность к работе.

## Что остаётся за пределами курса

PostgreSQL, ORM, Docker и CI объясняются на уровне назначения и следующего шага. Курс не обучает полноценной эксплуатации PostgreSQL, миграциям через Alembic, сборке Docker-образов или настройке всей инфраструктуры.

Асинхронность, Django/FastAPI, очереди задач, платёжные системы и масштабирование — дальнейшие темы. Перед публичным запуском проекта с пользователями отдельно нужны HTTPS, ограничение попыток входа, восстановление доступа и проверка конфигурации. У курса нет обещания трудоустройства или полного покрытия требований каждой вакансии.

## Проверка материалов для разработчика

Из корня проекта установи зависимости приложения и Flask:

```bash
python -m pip install -r requirements.txt
python -m pip install -r examples/web_notes/requirements.txt
python -m unittest discover -s tests -v
python tools/check_web_layout.py
```

Общий набор запускает все учебные примеры в отдельных временных папках, сравнивает ожидаемый вывод и проверяет три приложения. Внешняя сеть в примере HTTP-клиента заменена тестовым ответом. Проверки сохранения используют временные базы.

Проверка интерфейса открывает 42 урока и семь мини-проектов при ширине 1380 и 360 пикселей. Снимки находятся в `build/web-preview/`. Дополнительно проверь глазами переносы и выделения в новых уроках.
